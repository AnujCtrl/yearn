# Phase 1 build: rulings made during execution

Every decision the build controller made on Anuj's behalf while running the two plans with subagents (2026-10-27), in the order made. Each says what was decided, why, and what it costs if wrong.

## Receiver plan

- Ruling: work on branch `phase1` in place, not a worktree — EnterWorktree needs an explicit "worktree" from the user and the repo has no remote to branch from; a branch keeps main clean — cost if wrong: none, merge or delete the branch.
- Ruling: run the receiver plan first, then the Android plan, sequentially on the same branch (I told Anuj they could run in parallel) — SDD forbids parallel implementers, and the receiver fixes the wire contract the app mimics — cost if wrong: wall-clock only.
- Ruling: app PUT checks `store.status(id).stored` before staging to pick 200 vs 201 — simplest, matches contract — cost if wrong: a race returns 201 instead of 200, harmless.
- Ruling: T2 note/reindex tests that need commit are `async` — the plan wrote `def` by mistake — cost if wrong: none.
- Ruling: stage_file writes a sidecar `<index>.sha256` after the verified rename; status() reads sidecars (a file without a sidecar is not staged); commit still re-hashes every staged file — avoids re-hashing big videos on every GET, and a hand-made leftover without a sidecar is simply re-uploaded — cost if wrong: a re-upload of a leftover file.
- Ruling: Task 4 implementer runs the live check with `serve` in the foreground/background but never enables the systemd unit; I ask Anuj at the end — CLAUDE/memory rule "ask before system changes".
- Ruling (cross-plan): `files[].display_name` must be a string; an empty string is allowed (safe_name maps it to `file`); the phone never sends null (Android T3 sends `displayName ?: ""`) — FileEntity.displayName is nullable on the phone, and a null would otherwise be rejected as bad_record forever — cost if wrong: none, both sides agree.
- Ruling (cross-plan): `captured_at` accepts any ISO-8601 offset including `Z`; the phone always writes `+HH:MM` (pattern `xxx`) — cost if wrong: none.
- Ruling: accept uv picking Python 3.12.13 over system 3.14 — requires-python >=3.12 per brief, the systemd unit runs the project .venv either way — cost if wrong: nothing exercised on 3.14.
- Ruling: Task 4 `serve` calls store.reindex() before starting uvicorn — a crash between the folder rename and the index append otherwise leaves a stored capture out of index.jsonl forever (implementer concern) — cost if wrong: a startup scan of captures/, cheap at personal scale.
- Ruling: Task 3 auth is a pure ASGI middleware, not BaseHTTPMiddleware — the latter cancels the inner task on disconnect and wraps request.stream() — cost if wrong: none.
- Ruling: Task 3 adds three error bodies the contract table doesn't list: 400 bad_index (non-int index), 400 missing_sha256 also for a malformed X-Sha256, 422 bad_note (note body not {note:str, note_updated_at:str}) — the contract is silent; the phone maps any 4xx to Rejected (Android ruling) — cost if wrong: the phone shows "Desktop rejected the file" for its own bug.
- Ruling: Task 4 live check runs against a throwaway config + data root inside this SDD workspace, not ~/.config/yearn or ~/yearn-data — the real pairing token should be created when Anuj sets up the phone, not by a test run — cost if wrong: Anuj runs `yearn-receiver pair` himself (one command).
- Ruling: CLI errors (ConfigError, missing config) print one line to stderr and exit 2, no traceback — plan's Review Focus asks for "a plain message" — cost if wrong: none.
- Ruling: the fix wave takes both Importants plus minors 3,4,5,6,7,8,9,10,11(T4 PHONE_URL),notes-torn-line — each is a few lines and several turn a 500-forever into a recoverable state on Anuj's nearly full disk — cost if wrong: a slightly larger fix diff.
- Ruling: disk full answers 507 {"error":"disk_full"}; the phone's existing 5xx→Unreachable mapping keeps retrying and shows "Couldn't reach your desktop" (the fixed failure copy has no disk-full line) — cost if wrong: a vague reason on the phone while the desktop disk is full.
- Ruling: final-review minor 12 (test gaps: disconnect mid-PUT, chunked streaming through ASGI) parked — store-level tests cover cleanup and streaming — cost if wrong: an untested path at the app edge.
- Final: parked — sidecar can describe older content when two different uploads of one index finish at once — Ruling: real, deferred; commit re-hashes and the phone re-uploads, and the phone never sends different bytes for one index — cost if wrong: one extra upload.
- Final: parked — idempotent note repeat returns without fsync; pair test "8787 not in out" can flake ~1/400k — Ruling: nits, deferred — cost if wrong: a note line lost only if the process died between write and fsync and the same repeat then arrived.
- Final: parked — stage_file vs commit race (pre-existing, logged at Task 2) and reindex not checking record id vs folder — Ruling: deferred; one phone, uploads serialized by WorkManager unique work — cost if wrong: a 500 and a retry.

## Android app plan

- Ruling: CaptureRecord.full writes `display_name` as `displayName ?: ""` (never null) — receiver requires the key; same ruling in the receiver ledger — cost if wrong: none.
- Ruling: captured_at / note_updated_at / uploadedAt are formatted with `DateTimeFormatter.ofPattern("yyyy-MM-dd'T'HH:mm:ssxxx")` (always `+HH:MM`, never `Z`) — the T3 test regex requires it — cost if wrong: none.
- Ruling: ReceiverClient maps any other 4xx (e.g. 400 bad_id) to `Rejected(error, null)` → FAILED `Desktop rejected the file` — it is not retryable, and it shows up for Anuj to retry by hand — cost if wrong: a capture shows Failed instead of Waiting.
- Ruling: Task 1 declares INTERNET and ACCESS_NETWORK_STATE up front; Task 10 adds only REQUEST_IGNORE_BATTERY_OPTIMIZATIONS — network code lands in T7 and must work on a device before T10 — cost if wrong: none.
- Ruling: Task 10 Step 5 (device run) is not done by the implementer: it writes `docs/superpowers/plans/2026-10-26-yearn-device-check.md` with the 8 items unchecked; Anuj and I run it after the branch is built — it needs his hands on the phone — cost if wrong: device bugs surface later.
- Ruling: every Gradle run uses GRADLE_USER_HOME=/home/user/.gradle-local — 14,354 entries under ~/.gradle are root-owned (verified), and chown is a system change I won't make unasked; ~/.gradle-local is 1.5 GB of duplicated cache — cost if wrong: disk space; Anuj can `sudo chown -R anujp:anujp ~/.gradle` and drop the variable.
- Ruling: libraries pinned to the newest releases that support AGP 9.0.0 + compileSdk 36 (Compose BOM 2026.04.01, core-ktx 1.17.0, lifecycle 2.10.0, activity-compose 1.12.2, okhttp 5.3.2, haze 1.7.2, Kotlin 2.3.21, KSP 2.3.12, Room 2.8.5, WorkManager 2.12.0), not the absolute latest — the plan fixes AGP 9.0.0 / SDK 36 and the newest need SDK 37 / AGP 9.1 — cost if wrong: a version bump later.
- Ruling (from receiver final review, carry into Task 7): a 422 `hash_mismatch` on PUT or commit is transient (the staged copy changed under a race), so the uploader handles it like Unreachable: WAITING, `Couldn't reach your desktop`, attempts+1, retry=true; other 422s stay FAILED `Desktop rejected the file`. Any 5xx, including 507 disk_full, is Unreachable as planned — cost if wrong: a genuinely corrupt local file retries forever instead of showing Failed (unlikely: FileCopier hashed it at copy time).
- Ruling: CaptureRecord.full gives a PENDING file `error: "Copy not finished"` — only the raw view sees PENDING files (uploads need filesComplete) and the receiver requires exactly one of sha256/error — cost if wrong: wording in the raw view.
- Ruling: markInterruptedCopies returns the count of files changed, marks captures with no PENDING files left as filesComplete, keeps syncStatus — matches the brief's test (return 1 for one PENDING file) — cost if wrong: none.
- Ruling: pendingUploads orders oldest first; observeAll newest first — uploads in capture order — cost if wrong: none.
- Ruling: FileCopier Done.size = bytes actually copied (not OpenableColumns.SIZE); metadata query failures give null name, never a copy failure; any non-cancellation Exception → "Couldn't read this file: <message>"; cancellation deletes the .part and rethrows — the brief names only SecurityException/IO — cost if wrong: none.
- Ruling (Task 5, plan defect found in pre-dispatch read): YearnApp.onCreate runs markInterruptedCopies asynchronously, but a share that cold-starts the process inserts PENDING rows at the same moment, so recovery could mark a brand-new capture's files as "Copy interrupted" before they copy. CaptureService gets one extra ctor param `beforeFirstCapture: suspend () -> Unit = {}`, run once (under a Mutex) at the start of begin(); YearnApp passes a function that awaits the startup recovery job. Plus a test `begin_waitsForInterruptedCopyRecovery` — cost if wrong: one extra parameter.
- Ruling (Task 5): CaptureProgress.bytesTotal is null (the copier learns sizes only while copying); the sheet shows files done/total and bytes copied — cost if wrong: no percentage bar for one big video until build step 3.
- Ruling (Task 5): YearnApp holds an `AppGraph` (db, dao, copier, scheduler, service) that tests can replace (`YearnApp.graph` settable for tests), so Task 6's ActivityScenario tests run on in-memory Room — cost if wrong: none.
- Ruling: also fix in round 1 — YearnApp enqueues a sync when markInterruptedCopies() returns > 0 — the plan as written leaves recovered captures waiting for the daily job, against the spec's "upload soon" intent — cost if wrong: one extra WorkManager enqueue.
- Ruling (Task 6): the Inter font file is needed now (the sheet uses Inter) though the plan adds it in Task 9: Task 6 adds res/font/inter_variable.ttf (from google/fonts ofl/inter, OFL) + its OFL text at app/src/main/assets/licenses/LICENSE-Inter.txt (res/font accepts only fonts) and a tiny `ui/glass/YearnFont.kt` (`InterFamily`); Task 9 reuses it — cost if wrong: none.
- Ruling (Task 6): the note dot appears only in Saved (as in the POC) — finishing the activity ends the content-URI read grant, so nothing may finish the sheet while Saving; the copy stays in the ViewModel scope, progress flows through a StateFlow (onProgress arrives on IO) — cost if wrong: none.
- Ruling (Task 6): Fold8 is offline on Tailscale (last seen 16h) and adb has no device → Step 5 writes "blur check pending" in the commit message — cost if wrong: the early blur check moves to the device run.
- Ruling (Task 6): tests use a test Application (@Config(application=...)) that sets graphOverride (in-memory Room, fake copier) before super.onCreate — Task 5 reviewer note — cost if wrong: none.
- Ruling: fix it per the spec's "no duplicate captures" — keep the capture id in SavedStateHandle; a restored activity whose ViewModel is fresh but whose saved state names a capture finishes quietly (the capture exists; startup recovery already marked its unfinished files) — the plan's ViewModel flag only covers config changes — cost if wrong: after a process kill mid-copy Anuj sees the sheet vanish instead of a resumed copy (the read grant is unreliable then anyway).
- Ruling (Task 7): on Unreachable the uploader marks that capture and stops the run (the rest stay WAITING) — avoids N×10 s timeouts when the desktop is off — cost if wrong: none, the retry covers the rest.
- Ruling (Task 7): Unauthorized marks the current capture FAILED and stops the run; Rejected marks it FAILED and continues with the next — a bad token affects every capture, a rejected record only one — cost if wrong: one Failed row per sync until Anuj fixes the token.

- Ruling (revises my Task 7 ruling 3): transient hash_mismatch marks that capture WAITING + retry=true but CONTINUES with the next capture instead of stopping the run — a locally corrupt file would otherwise block every later capture forever (review minor 4) — cost if wrong: none.
